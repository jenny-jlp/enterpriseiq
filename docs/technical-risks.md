# 技术风险与数据限制（M0）

调研日期：2026-11-05。本文区分已观察到的事实和需要运行验证的风险。P0 表示进入可信调查闭环前必须处理；P1 表示扩展场景/生产化前处理；不代表当前已存在生产事故。

具体来源、统计和方法见 [数据审计](dataset-audit.md)；框架能力引用见 [候选架构](architecture-proposal.md)。

## 已完成验证的边界

本轮确认指定主键/外键、组件层级、记录数量、代表性证据链、ARR 精确计算和 SLA 题目代理计算；三个归档哈希与官方 manifest 一致。只对 PM 的纯解析函数做隔离兼容探查，其他工具行为为源码审查结论。

未验证网络工具调用、数据库导入、模型质量、LangGraph 运行恢复、租户隔离、吞吐和真实成本。**没有模型成绩，不宣称生产可靠。** README 与数据包的 KB 数量差异（22/55）已记录，不默默修正上游数据。

## 进入 M1 前保留的决策

1. 固定首批调查样本和评判口径，特别是候选影响、敞口与未知状态的措辞。
2. 明确外部模型/trace 的数据边界；模型与部署不在 M0 锁死。
3. 先验证关系计算、证据完整性、暂停恢复和权限，再扩大风险类型与页面范围。

如果原始数据无法支持某项承诺，应缩小产品声明或补数据；不通过更强模型掩盖缺字段和不完整查询。
