# EnterpriseIQ — 里程碑路线图

更新日期：2026-11-09。此路线图只保留阶段目标和退出标准，不构成整个项目的详细实施计划；后续阶段根据上一阶段证据调整。

## M0 — 产品与技术调研（本轮交付）

**实际完成：** 固定官方仓库提交；检查目录、Schema、14 个任务问题和其中 10 份评分标准；下载并核验三个小型官方归档；检查数据关联与工具源码；形成产品范围、候选引擎、技术取舍和风险清单。

**关键选择：** 建议混合引擎；关系查询与金额由确定性逻辑负责，Agent 负责有边界的证据调查和综合；Case、Evidence、Checkpoint 分责。建议 Python/LangGraph/FastAPI/PostgreSQL，前端候选 TypeScript/React/Next.js。均未开始实施。

**必要验证结果：** 指定主键/外键和产品层级检查通过；Vantara 代表链存在；12 个 P1 相关产品区域中最高 ARR 为 732,000；SLA 官方票龄代理复算 27 条。确认无首响时间、KB 文档数差异、查询截断与 PM 解析限制。框架能力完成文档核验，尚无运行结论。

**交付物：** [产品概览](product-overview.md)、[数据审计](dataset-audit.md)、[候选架构](architecture-proposal.md)、[技术风险](technical-risks.md)、本路线图。

**退出标准：** 能说明数据支持哪些场景、关键关联如何成立、候选架构为何适合、哪些能力尚未验证。M0 不要求 Agent 跑通、界面或 Docker 环境。文档已达到调研交付范围；核心产品口径待用户评审。

**值得深入理解：** 共享组件与根因的区别；区域/全局 ARR 去重；Checkpoint、证据和人工决策各自记录什么。

## M1 — 核心可行性与可靠性验证（建议下一步）

**目标：** 验证最小调查闭环是否可信，不扩建全部工作空间。

**范围与交付：** 以 eng-l1-a、eng-l2-a 和 Vantara 阻塞调查作为代表样本，验证版本化数据连接、受约束工具、LangGraph 状态/暂停恢复、原始证据引用与人工决定；交付可复查的验证结果和更新后的架构决定。

**退出标准：** 结构化结果与固定数据基线一致；重要结论引用可解析、无虚构 ETA；非法/截断查询不冒充完整结果；重启和重复 resume 不产生重复审核/归档；两个测试身份的越权读取与恢复被拒绝。记录重复调查质量、失败类型、调用量/成本/延迟，并据结果决定继续、调整或缩小范围。Agent 通过率阈值、样本规模和预算在开始前明确。

**依赖与核心参与：** 评审 M0 业务口径；确定模型数据边界和访问方式。用户重点掌握 state/reducer、关联工具契约、恢复语义和评测方法；普通环境搭建由助手承担。需要凭据时再按实际选择配置，M0 未读取或配置凭据。

## M2 — 调查能力增强与 CLI 最小审核闭环（用户已确认）

**目标：** 在 M1 已验证的动态调查基础上，增强任务界定、证据缺口管理和有边界恢复，并让结果形成可追溯的人工审核决定。M1 已于 2026-11-06 最终验收并合并 main。

**五项交付：** 显式任务契约与澄清；证据缺口驱动调查；有限重试与恢复互斥；Case/报告版本/审核事件 CLI 闭环；保留 M1 的综合验收与核心讲解。用户已于 2026-11-06 原则认可交付及两项评分争议的 Codex 语义复核，授权工程收尾。

**退出标准：** 原三场景各三次回归及两个新增调查各三次，自动评分、Codex 原文复核和用户验收分开记录；金额/实体集合/引用错误不能通过；澄清等待不消耗正常暂停的执行预算；验证故障重试上限、跨进程互斥与恢复；完成可回溯的修改/接受/驳回/后续调查，阻止陈旧审核及 blocked 报告接受。实际结果持续记录在 PROJECT_STATUS。

**范围调整：** 用户选择引擎优先＋最小审核闭环。原 M2 的 Risk Center、Studio、Cases 三工作空间 Web、风险信号入口顺延，不在本轮扩建；此调整不代表已承诺某个后续里程碑的交付日期。不重做 StateGraph、动态工具、结构化查询、ReportVerifier 或最小 Checkpoint。

**核心参与：** 用户重点理解任务契约、State/reducer、Agent 与 Workflow 的职责边界、工具证据、恢复与人工决定的区别。最终验收后才整理提交，不自动进入 M3。

## M3 — 最小调查工作台与试点准备（2026-11-09 已批准）

**目标：** 判断能否从合成快照走向授权的真实数据试点。

**交付与退出标准：** 增加独立场景与故障评测、明确权限和数据保留策略、完成成本/性能及版本恢复评估；如接真实系统，验证身份映射、分页、增量变化和证据可追溯性。达到约定门槛后再决定试点部署与外部写操作范围；基准成绩不能代替企业接入验收。

**核心参与：** 误报/漏报权衡、生产可靠性指标和可接受的风险边界。

**确认范围：** 最小 Web 调查工作台为核心；其余四项为最小身份授权、分级评测与版本恢复、模型预算及成本性能、最小数据生命周期与接入契约验证。沿用 FastAPI + React/TypeScript + PostgreSQL；Web/API 与单 worker 通过 PostgreSQL 作业登记解耦，不重构 M1/M2 引擎。viewer 只读，investigator 发起和恢复自己的调查，reviewer 审核他人发起的调查；后端禁止自审。真实连接、完整三工作空间、多租户/SSO、外部写入与生产部署留待 M4 或更后。

**评测边界：** 确定性回归和离线复验优先，必要时少量冒烟；21 次冻结验收保留，金额、引用和资源授权关键错误必须为零，不为单个修复反复整批重跑。初定累计上限为 30 次真实调查（开发冒烟最多 9 次、冻结最多 21 次）、180 次模型请求、120 万 token、估算人民币 30 元，任一先到即停；包含失败、重试及未知用量预留。数据保留只解决当前存储的生命周期，不建设通用治理平台，不破坏保留报告的证据引用。
